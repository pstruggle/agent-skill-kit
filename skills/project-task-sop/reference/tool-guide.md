# 工具使用指导（v3.0）

> 纪律：每次 `read` 前先问"我真的需要全文吗？"；会话内不重复读已读文件；优先用索引和摘要。

| 工具 | 适用场景 | 最佳实践 | 禁忌 |
|------|----------|----------|------|
| `read` | 上下文/代码/模板 | 按需读取；AGENTS.md 只读索引；大文件用 `offset`/`limit` | 一次性读全量；重复读已读文件 |
| `write` | 创建新文件 | UTF-8 no-BOM、LF；单次写入完整内容 | 追加写入用 `edit` |
| `edit` | 追加/更新 | 精确 `old_string`；大文件用锚点定位 | 不必要的 `replace_all` |
| `glob` | 发现文件 | `pattern` + `path` 限定；排除构建产物 | 大仓库无限制全量 |
| `grep` | 搜索模式 | `include` 限定语言 | 无 `include` 全量搜索 |
| `pwsh`/`bash` | 命令执行 | 显式 `workdir`；超时设置 | 交互式命令、无超时长跑 |
| `python` | 运行 sop.py | `python sop.py <cmd>`；本项目所有机械逻辑已封装 | 手算哈希/锚点/渲染 |
| `subagent` | 并行维度分析、长任务 | 独立完整 prompt；`run_in_background: true` | 简单查询滥用子代理 |
| `web_search` | 最新方案/报错 | 1–3 精准查询；引用来源 | 宽泛查询、不验证来源 |

## 与 sop.py 的分工

- **机械**（脚本做）：脚手架、锚点哈希、查重、记录、渲染、校验、token 估算、教训检索。
- **语义**（agent 做）：架构判断、技术栈解读、测试策略、风险识别——填充维度文件的"维度内容"段与 plan 的语义字段。
- 脚本输出只是清单与原始事实，不要照抄进维度文件；写入的是**你的分析结论**。
- **教训检索**：`python sop.py lessons <task> <关键词>` 检索 NOTES.md 的 `## 教训:` 条目；教训由 agent 在解决坑后沉淀（症状/根因/对策/验证）。
