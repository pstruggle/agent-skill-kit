# 流程收敛（聚合思维）— 按需加载参考

> 仅当任务的**目标本身是梳理/再造业务流程、设计工作流、沉淀业务 SOP** 时读取本文件
> （例：代理分佣流程、获客链路、交付流程、审批链路、渠道开通流程）。
> 普通代码/开发任务不读取。聚合思维是通用方法论，SOP 是执行纪律——
> 本文件只补 SOP 未内化的「流程要素筛选判定」这一具体工具，**不新增执行步骤、不新增维度**。

## 3. 流程收敛 5 步（简版）

1. **定目标**：一句写清"在【约束】下，稳定产出【交付物】、达成【指标】"。之后所有环节用它当筛子。
2. **发散收集**：先摊开角色/动作/输入/输出/分支/异常/风险/依赖，**不筛选、不排序**。
3. **定筛选标准**：用四类标尺（§4）统一判定，不凭感觉选。
4. **收敛重组**：抽主线（正向最优链路，尽量短）+ 分支（异常/审批/复核/作废）。
5. **闭环校验**：三问终审（§5）。

## 4. 流程要素筛选判定表（核心增量工具）

逐条要素过三问：

1. **达成目标必须？** → 非必要，剔除
2. **能合并进别的步骤？** → 重复/相似动作合并
3. **前置条件满足且位置正确？** → 否则调整时序

四类收敛标尺：

| 标尺 | 判定问题 |
|------|------|
| 时序 | 事情发生的先后顺序对吗？ |
| 主体 | 谁来执行？责任边界清晰吗？ |
| 类型 | 属主流程 / 异常分支 / 复核兜底？ |
| 价值 | 对目标有贡献吗（必要 / 可选 / 冗余）？ |

归一原则：不同入口、不同端（H5/小程序/后台）的同类操作，尽量收敛成一套底层逻辑。

## 5. 闭环校验三问（终审）

1. 起点到终点能否跑通？有无断点、缺数据？
2. 所有分支有无兜底？失败之后去哪里？
3. 是否仍有多套可行方案？→ 选**最优方案作为标准流程**，其余作备注，不进主流程。

## 7. 纪律

- **按需加载**：仅流程梳理/再造类任务读取；勿常驻主流程、勿纳入每任务必读。
- **轻量产出**：一次梳理交付 1 张流程梳理表 + 1 份收敛后流程即可，不额外造文书。
- **不越界**：不新增维度、不新增执行步骤、不改决策门；它只是流程梳理任务的工具。
